Cookie banner slider — fix proof

The analytics toggle in the cookie consent modal was invisible in its disabled state (clickable, but the slider track and knob rendered transparent). Below is the evidence: the bug reproduced and the fix verified, both captured live from the running dev site.

File: src/components/cookie-though-layout.css Source: live Gatsby dev server at localhost:8765 Tool: Playwright (Chromium)
Verdict: PASS — disabled slider is now visible; enabled slider unchanged.

Root cause

cookie-though renders inside a Shadow DOM and styles its slider via CSS custom properties. The project's override file pointed --ct-slider-primary and --ct-slider-secondary at --gray-400 / --gray-300 — variables that are not defined anywhere in the codebase. CSS resolves an unset var() to the property's initial value, so the slider's background resolved to transparent. The --ct-slider-enabled-* variables had real hex values, which is why the slider only appeared once toggled on.

The change

/* src/components/cookie-though-layout.css */
/* The colors used to style the sliders */
--ct-slider-primary:   var(--gray-400);   /* undefined → transparent */
--ct-slider-secondary: var(--gray-300);   /* undefined → transparent */
--ct-slider-primary:   var(--ct-text);    /* defined: #6b7280 */
--ct-slider-secondary: #d1d5db;           /* light gray track */
--ct-slider-enabled-primary:   #4c4cff;
--ct-slider-enabled-secondary: #b3b3ff;

How the "before" screenshots were produced

To compare states cleanly in a single browser session, the "before" screenshots were captured by re-pointing the two slider CSS variables back to the broken var(--gray-400) / var(--gray-300) values on the live host element, then re-toggling. This is the exact same defect the fix removed — no other styles were touched.
